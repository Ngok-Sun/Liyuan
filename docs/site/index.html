PART 01

第一板块 · 初步介绍与安装

1.1 梨园是什么

梨园是基于 pi 构建的 RP Agent，将软件工程 Coding Agent 的诸多核心范式映射到角色扮演与故事创作中。

在传统前端中，大模型仅仅作为被动接收单次提问并输出纯文本的补全接口，容易引发长文本遗忘、设定漂移、提示词无休止堆叠等问题。梨园全面引入智能体循环、沙箱物理隔离与工件化工作流：

Coding Agent 能力 梨园 RP 化映射 实际功能与机制体现
工作区隔离（Workspace / cwd） 角色卡独立空间（一卡一目录） 每张卡为一个独立的物理工作区，会话、记忆、设定与素材物理聚合，直接拷贝即可无损跨机迁移。
代码（Code） 剧情正文（Story Prose） 将叙事正文视为活的创作工件，区分扮演气泡与 Agent 一章一文件（正文/*.md）双模式。
局部改写（Edit / Patch） 局部定点修改 精准匹配原文指定行进行增删改，杜绝为了修改几句话而全盘重写的昂贵浪费。
文件检索（Grep / Search） 世界书与记忆检索 模型在下笔前通过工具主动查阅设定集与过往记忆，不在常驻上下文里塞满无用词条。
版本快照（Rewind / Checkpoint） 检查点与分支回滚 具备内容寻址的轻量快照仓（历史/），随改随存，支持任意改动行级 diff 与回退。
上下文压缩（Compact） 剧情前情提要接力 根据叙事脉络提炼接力摘要，原文归档入库，保持活动提示词窗口轻盈黑润。
权限确认（Permission Gate） 剧情分岔决策卡（ask 工具） 遇到重大剧情分歧时主动停笔，通过选择卡交由用户决策故事走向，实现人机真正共创。
规则分层（SYSTEM / AGENTS） 提示词三层体系 引擎底层协议、全局追加准则与卡片世界法则分层存放，支持条目级单独开关。

1.2 双形态创作体系：Roleplay 模式与 Agent 模式

梨园提供两套相互平行、分流管理的创作模式，在会话树中各自拥有独立切签：

  • 🎭 扮演模式（Roleplay Mode）：主打沉浸式剧情推演。底层技术调用在后台封闭，正文在消息流中作为拍级工件呈现，具备时间/地点/状态账本、登场名录与分支世界线回溯。
  • 📖 Agent 模式（Prose Agent Mode）：趋近于一般的 Coding Agent。正文与讨论层彻底分离：讨论区负责探讨、下达指令与修改意见，正文按「一章一文件」（正文/001-章名.md）持久化落盘，模型通过原生工具精准编辑文件，具备本地快照仓与行级 diff 回显。

1.3 安装与部署方式

梨园提供桌面客户端（免配置环境）、Docker 预构建镜像、源码本地运行以及 VPS 服务端无头部署四种方式：

方式一：桌面安装包（推荐，开箱即用）

前往 GitHub Releases 最新发布页 下载对应操作系统的安装包：

操作系统 分发文件 说明
Windows Liyuan-*-win-desktop-setup.exe 标准 NSIS 安装包，双击安装，支持应用内自动检测更新。
Windows（便携版） Liyuan-*-win-desktop-portable.zip 解压后直接双击 Liyuan.exe 运行，免安装，不写注册表。
macOS Liyuan-*-mac-desktop-arm64.dmg / -x64.dmg 提供 Apple Silicon 与 Intel 双版本。首次运行需在「系统设置 → 隐私与安全性」允许。
Linux Liyuan-*-linux-desktop.AppImage 执行 chmod +x 赋予执行权限后直接双击运行。

桌面版采用「白瓷朱砂」极简呼吸启动界面，开窗彻底不闪黑。首次启动会引导选定数据目录（默认在系统的文档目录下），卡片、会话、记忆全部独立存储于该目录，重装或升版应用绝不丢失数据。

方式二：Docker 容器部署（推荐服务器部署）

官方提供已构建完成的双架构镜像（amd64 / arm64），服务器无需安装 Node.js，拉取即跑： 

mkdir -p liyuan && cd liyuan
curl -fsSL -o docker-compose.yml https://raw.githubusercontent.com/weidu12123/Liyuan/master/deploy/compose.ghcr.yml
docker compose up -d

# 升级至最新版本
docker compose pull && docker compose up -d

镜像地址为 ghcr.io/weidu12123/liyuan:latest。数据目录自动挂载于宿主机当前目录的 ./data/ 下，便于备份和迁移。

方式三：源码本地运行

要求系统安装 Node.js ≥ 22：

# 1. 克隆代码仓库
git clone https://github.com/weidu12123/Liyuan.git && cd Liyuan

# 2. 准备配置文件
cp liyuan.agent.example.json liyuan.agent.json
cp liyuan.config.example.json liyuan.config.json

# 3. 安装依赖并启动
npm install
npm run web:build    # 编译前端
npm run web          # 启动服务，浏览器打开 http://127.0.0.1:7620

Windows 环境可双击 start.bat，Linux / macOS 环境执行 ./start.sh。

⚠️ 端口安全警告
梨园默认端口 7620 在未配置访问密码前为全开放状态。部署到公网或局域网共享时，请在启动后第一时间进入界面「系统设置」设置访问密码。
PART 02

第二板块 · 快速上手指南

仅需完成以下四个关键操作，即可开启第一场高质量沉浸式创作：

第一步：配置访问密码与基础防护

点击左侧导航轨底部的「齿轮图标（设置）」，在「访问密码」卡片输入至少 4 位字符的密码并保存。拦截未授权的公网探测与额度盗刷。

第二步：配置模型连接（API 接入）

点击左侧导航轨的「插头图标（连接）」，点击「+ 生成配置」，填入服务商的 API 端点、Key 与模型名称：

  • 思考档 (Thinking Mode)：日常流畅对话建议设为 off，需要极深剧情逻辑推演时设为 low。非思考模型必须设为 off。
  • 上下文窗口 (Context Window)：建议填写 128000 (128k)。
  • 最大回复 tokens：默认推荐 16384 (16k)，满足一拍内多段落长文输出。
  • 流式传输：保持勾选状态，享受实时打字机渲染。
第三步：挑选角色卡并选择创作形态

点击左侧顶部的「角色库图标」，选择内置示例卡或导入卡片：

  • 开启沉浸扮演：在左栏选用开场白分支，直接点击「开始对话」；
  • 开启 Agent 独立写小说：点击「新建项目」，勾选「📖 正文 Agent」模式，第一幕将自动落成 000-开场.md，进入正文一章一文件创作模式。
第四步：让 Agent 人机协同写卡与自建世界

手头没有满意的角色卡？将顶栏模式切为「工作模式」，在对话框直接说：“我想做一张修仙门派长老的角色卡，请帮我规划背景与技能，并录入工坊大纲”。背后的 card-authoring 技能会自动调度工具集，遵循规范自动生成并落盘保存。

3.1 主交互与会话树管理

主工作区包含全局导航轨、会话树项目管理栏、主视窗对话区与底部自适应工具栏。

主交互全景图解
点击可放大查看
会话树与项目管理核心升级
  • 双模式胶囊分流 顶部提供 [ 🎭 扮演会话 | 📖 正文 Agent ] 两个专属 Tab，各自统计项目数量，彻底终结两类形态混杂的混乱。
  • 解禁当前项目平滑删除 解除当前打开项目的删除死锁，无论是否活动项目均可直接删除。删除当前项目时系统自动平滑切入下一个项目（或新开空白项目），无缝过渡。

3.2 外观主题中心（Theme Center）

左侧导航轨提供调色板入口，打开 370px 独立抽屉，带来通透清澈的沉浸式视觉定制：

三大视觉核心能力
  • 预设主题宫格与 16:9 实时预览 内置「白瓷朱砂」「玄黑赤金」「千里青绿」「青花瓷韵」「落樱微雨」「沧浪寒潭」6 套精选主题，上部大视窗跟随点击实时联动，全局一键换肤。

  • 自定义 CSS 样式注入 支持直接编写自定义 CSS 规则或导入样式文件，带有一键启用/停用开关，为进阶玩家开放绝对自由的样式控制权。

3.3 Agent 模式正文独立创作工作流

将 Coding Agent 工作流完整迁移至长篇正文写作：

正文工件与沙箱物理隔离
  • 一章一文件 正文按 正文/001-章名.md 在磁盘独立排列，文件名即阅读顺序。正文完全开放原生读写，不再污染对话历史。
  • 快照仓与行级 Diff 每次改动在 历史/ 沉淀内容寻址快照与检查点，过程条展开显示绿色/红色行级差异，随时双击恢复或回到某次输入。
  • 多项目物理隔离守卫 沙箱底层严格以当前项目为界，严禁任何工具跨项目读取、编辑、搜索或探测，保障卡下各个小说的绝对独立纯净。
  • 双端自适应交互 桌面端支持鼠标拖拽正文与讨论的比例（20%~85%），双击恢复 60%；手机端支持顺畅的双轨滑动手势。

PART 04

第四板块 · 常见问题与注意事项 (FAQ)

Q1：扮演模式、工作模式与 Agent 模式有什么区别？何时选用？
  • 🎭 扮演模式：用于与角色沉浸式演播。技术细节被封闭，正文在气泡中流式展现，自动记账好感与世界状态。
  • 📖 Agent 模式：用于长篇小说/剧本独立创作。正文与讨论区彻底分流，讨论出结论后模型自动落盘为一章一文件（001-初雪.md），具备本地快照仓与行级 diff。
  • 🛠️ 工作模式：在扮演中随时切入边聊边改卡片、调试前端正则或增删词条，改完切回扮演继续演出，调试 chatter 不污染剧情。
Q2：同一角色卡下面的多个独立项目，如何确保互不读取和污染？
梨园在 v1.6.3 建立了双重物理隔离守卫：
  1. 沙箱路径守卫 (isOtherChatPath)：任何原生工具读取、修改、搜索或列出同卡下其它项目目录的操作，会被沙箱底层直接 DENY 拦截；
  2. 状态块摘要阻断：Agent 模式的状态块恒不接入卡级跨项目常驻摘要，前情提要只认当前项目自身正文生成的摘要，新项目开局 0 污染。
Q3：删除项目或会话后，如何保证不留下任何记忆残留？
在会话树中点击项目行的红色垃圾桶删除项目时，系统会：
  1. 递归彻底删除子项目目录（包含正文、历史快照、会话、状态账本、面板与向量记忆）；
  2. 同步物理删除卡文件夹内的复盘文件（记忆/局/.md）；
  3. 从清单中注销并登记进遗忘名单，驱动重新合并，彻底抹除已删局的所有剧情事实。
若删除的是当前正在打开的项目，系统会自动平滑切至同模式其它项目（或新开空白项目），体验丝滑无阻。
Q4：为什么删除世界书后，卡档案里的世界书条目不会变成“无主残留”？
在 v1.6.3 中，卡档案（AGENTS.md）底稿建立时不再硬编码抄录世界书常驻条目，世界书条目 100% 由动态镜像机制（syncLorebookMirror）独立持有并带上来源后缀。删除或更换世界书时，系统会自动剥除历史遗留条目，绝不制造或遗留无主条目。
Q5：旁路模型（Side Model）用于记账为什么必须关闭思考？
旁路模型用于在每轮末尾异步更新变量账本与人物名录。记账属于快速结构化提炼，必须将思考档设为 off。若开启思考，每轮末尾可能需要额外等待几十秒甚至几分钟，极大拖慢推演节奏。
Q6：连接 API 时遇到 400 报错或 Invalid Argument 怎么处理？
请对照以下三点快速排查：
  1. 思考档位 (Thinking Mode)：非推理型模型不支持思考参数，传入思考档名会导致接口拒绝，请设为 off；
  2. Base URL 端点格式：中转聚合站或第三方反代地址末尾是否正确补全了 /v1 或 /v1/；
  3. 上下文容量上限：确认填写的 Context Window 数值未超过该模型所允许的最大输入边界。
Q7：如何把角色卡、会话与记忆数据完整迁移到另一台设备？
梨园采用一卡一目录的物理独立设计：
  • 单卡无损迁移：只需将数据目录下的 cards/角色名/ 文件夹完整拷贝到新设备的对应目录下。其下的全部历史会话、正文、卡级记忆与提示词自动保留。
  • 整站全量备份：在「设置 → 备份与恢复」中点击「导出」下载 zip 全量快照；在新环境中点击「导入」即可一键恢复全部卡片、API 连接配置与全局设定。
